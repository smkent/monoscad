# Environment/Tools

* `mise` manages dev tools and tasks.
* `mise install`: After-clone setup (install tools, pre-commit hooks)
* `mise run lint`: Pre-commit hooks (via `pre-commit`-compatible `prek`) including lint and format checks
* `mise run test`: Run tests, if any are defined
* `mise run lt`: Lint+test (no arguments)

# Commit conventions

* Keep commit messages concise and in plain language, so a maintainer can
  quickly understand the change. Use a short subject, and add a body only when
  the change needs explaining, in a few lines about why. Don't list changed
  files, restate the diff, or report test results.
* If a commit contains code or text largely generated by an LLM, add an
  `Assisted-by: <tool>:<model>` trailer, for example with `git commit --trailer`.
* Don't add `Co-authored-by` or `Signed-off-by` lines for LLM tools, links to
  LLM sessions, or promotional lines such as "Generated with [...]".

# Submitting contributions

* You may commit locally without asking. Before submitting anything, such as
  pushing commits or creating or editing a pull request, issue, or comment,
  show the user (who is the contributor) exactly what will be submitted, and
  wait for their explicit approval. Submit it as approved. This includes but is
  not limited to commit messages, titles, and bodies.
* Keep titles and descriptions short and specific. Don't restate what the diff
  already shows.
